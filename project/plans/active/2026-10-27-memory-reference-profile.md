# 2026-10-27 Memory Reference Profile

## 目标

在 10 月 27 日中期检查前，把 Memory 做成 Nous Wave 第一条完整纵向能力：从材料与观察、证据、长期认知，到检索、真实使用反馈、生命周期、恢复和来源追溯形成闭环。

长期架构继续按 Architecture-Vault 设计。中期交付不缩减目标设计。

## 进入实现前需要关闭的设计问题

Memory Spec 开始前至少明确：

- 陈述性 Memory 的对象身份连续性；
- Evidence 的来源依赖与佐证聚合；
- 认知角色和形成方式的稳定语义；
- 修订、派生、矛盾、世界状态变化之间的表示关系；
- 使用事件的幂等身份和语义类别；
- 查询计划、多视图聚合和服务投影的稳定合同。

这些问题形成设计决定后，再写可执行规格。

## Memory 纵向能力

中期实现覆盖：

- Artifact、ObservationOccurrence、Evidence 与来源谱系；
- MemoryObject、不可变修订、对象纪元和生命周期；
- 认知角色与形成方式；
- 实体指向与来源提及；
- 修正、重新解释、派生和矛盾；
- 抑制、恢复与清除；
- 幂等的长期使用事件；
- 精确、实体、词项和稠密基础检索；
- 固定 QueryPlan、对象级多视图聚合与稳定融合；
- 返回前权威状态核验；
- 服务代次、重建和进程重启后的恢复；
- 从 Memory 回溯到观察与来源。

## Self 中期能力

Self 保持独立认知系统。中期只提供数份只读结构化文档，例如身份、自我认知、人格与表达倾向、价值偏好和叙事。它们来自主体绑定的 Cognitive Seed 版本，不在本阶段实现自动演化。

## 不作为中期硬依赖

Social Cognition、Motivation、完整 Episode/Journal、认知图式自动形成与拆分合并、高级联想拓扑和 Offline Cognition 均继续设计，不进入 Memory 主链的验收条件。

## 下降顺序

1. 关闭 Memory 与 Evidence 的剩余中层设计问题。
2. 编写 Memory 语义规格。
3. 编写查询与服务投影规格。
4. 编写持久化、接口、事务、幂等和恢复规格。
5. 按规格重构现有实现。
6. 完成端到端场景和资格验证。

## 中期演示

演示从真实材料摄入开始，形成多条长期记忆；随后用新证据修正或形成矛盾，保留完整来源；再以不同表达检索同一认知，展示召回和真实使用的区别；重启后状态仍可恢复；最后完成抑制、恢复和来源追溯。
