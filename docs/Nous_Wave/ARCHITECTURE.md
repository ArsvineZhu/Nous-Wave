# Current Nous Wave Architecture

**Status:** current-state architecture
**Scope:** semantic ownership and durable system invariants.
**Physical implementation defaults are recorded separately in `DECISIONS.md`.**

## 1. System identity

Nous Wave is a long-lived **Subject cognition system**.

It is not a vector database, prompt manager, message store, graph database, or Memory-only service.

External systems own their canonical world/application state. Nous Wave owns the Subject's cognition of, memory of, activation around, and access to that state.

Core invariants:

```text
Subject != Model
Artifact != Memory
ObservationOccurrence != Artifact
Message != Memory
Tool result != Truth

stored != active != foreground != projected != used != reinforced != truth

runtime remembered != durable memory formed
reading != learning
retrieval != internalization

runtime eviction != cognitive forgetting
cognitive forgetting != suppression != purge

Entity identity != surface name != embedding similarity
Resource availability != Resource contents
Serving projection != Cognitive Authority
model cache != semantic cognitive runtime
```

## 2. Subject initialization

A Subject can be created from:

```text
Subject identity
+ Character Seed
+ basic configuration
```

The Character Seed is human-authored free-form source material. It is retained with provenance/history.

It is not current Persona state. Future Persona/Self cognition may interpret or diverge from it.

A Subject MUST NOT require preloaded memories, social relationships, beliefs or a persona ontology to exist.

## 3. Cognitive ownership

### 3.1 Subject Core — required

Owns:

- Subject identity and lifecycle;
- Subject initialization and Character Seed lineage;
- Subject-level configuration relevant to cognition;
- MicroSystem availability/readiness declarations;
- stable Subject-level semantic dependencies.

Subject Core must not depend on Memory.

### 3.2 Cognitive Runtime — required

Owns model-independent cognitive continuity:

- Session;
- ResidentSet;
- consumer-specific working-set derivation;
- use/activation events;
- context contribution;
- cognitive query orchestration boundary;
- capability/resource awareness;
- request-local/call-chain Work Cycle state where used.

The semantic runtime survives process/model/provider changes according to its persistence semantics.

It is not a model KV cache.

### 3.3 Memory MicroSystem — optional

Memory is the first fully implemented optional cognitive MicroSystem and is enabled in the reference profile.

It owns:

- Specific/Episodic Memory;
- Integrative Memory;
- Procedural/Experience Memory;
- Memory object/revision/evidence semantics;
- formation, revision, consolidation;
- Tags, Anchors and Memory-owned association evidence;
- forgetting/accessibility, suppression and purge semantics;
- Memory recall contribution to Cognitive Query.

Memory must not own Subject Core or generic Cognitive Runtime.

### 3.4 Future cognitive MicroSystems

Persona/Self, Social, Epistemic, Goals/Commitments, Reflection, Diary and Dream/Simulation are FUTURE.

Only cross-MicroSystem boundaries may exist now.

Do not create empty placeholder crates.

## 4. MicroSystem model

```text
MicroSystem
= semantic owner
+ typed operations
+ explicit dependencies
+ readiness/capability
```

A MicroSystem is not a process/container/network service/plugin marketplace.

MicroSystems use explicit static composition. The authorized Architecture Rebase target is a TypeScript Cognitive Host supervising a Rust Cognitive Kernel, exposed through Core + official Client. The existing Rust deployment is being migrated under [IMPLEMENTATION_SPEC.md](IMPLEMENTATION_SPEC.md).

## 5. Cognitive material and evidence

Cognitive material is broader than messages and text chunks.

Input may include:

- short/long text;
- messages/conversations;
- files/documents;
- Markdown/HTML/JSON/code;
- browser/search/tool/API/database results;
- images/audio/video;
- host events;
- imports;
- future self-generated artifacts.

The following are separate:

```text
receive
persist
index
interpret
form durable memory
activate
learn/reinforce
```

### 5.1 Artifact

Raw/received/generated bytes or immutable payload identity.

### 5.2 ObservationOccurrence

A distinct Subject encounter with material.

Identical bytes may appear in many occurrences.

### 5.3 SourceRegion / DerivedRepresentation / DerivedRegion

Stable source coordinates and immutable derived interpretations retain exact provenance and producer identity.

Provider replacement creates new derived representations; it does not mutate historical interpretations.

## 6. Cognitive Resource Awareness

Nous Wave may know that an external authoritative resource exists without copying its contents.

A Resource can expose:

- coverage/authority class;
- query dimensions;
- modalities;
- freshness/liveness properties;
- access cost;
- readiness.

Progressive access:

```text
resource exists
→ inspect lightweight coverage
→ query relevant records
→ materialize exact evidence
```

## 7. Cognitive addressing

Cognition is addressed through multiple channels:

```text
Exact
Semantic
Topological
Resource
Runtime
```

Exact identity is not implemented with embedding similarity.

Semantic retrieval projections are serving mechanics.

Topological retrieval includes Tags, Anchors, typed associations and bounded associative expansion.

## 8. Tags, Anchors and Associations

### Tags

Tags are typed/provenanced cognitive topology primitives. They are not merely topic strings.

### Anchors

Anchors are explicit/revisioned cognitive landmarks or convergence/routing points. Their identity is not an average vector.

### Associations

Associations represent experiential, temporal, causal, procedural, co-activation or other cognitive structure.

Association is not embedding similarity.

## 9. Cognitive Runtime

### Session

A durable/recoverable Subject continuity scope.

### ResidentSet

References currently available to the Session.

Residency does not imply durable Memory formation.

### ConsumerWorkingSet

A bounded, ephemeral projection for one concrete consumer/invocation.

Different consumers over the same ResidentSet may receive different working sets.

This is a semantic requirement.

### ContextContribution

Nous contributes structured context/evidence. The Host may own final prompt/context composition.

### Cognitive Work Cycle

A local request/call-chain optimization seam only.

It may preserve:

- explored frontier;
- inspected candidates;
- local activation;
- continuation metadata.

It is not a long-lived top-level runtime owner and is not required to be durable.

## 10. Cognitive I/O

The public semantic boundary distinguishes:

```text
Observation / Material Input
Cognitive Query
Runtime / Use Feedback
Materialization / Evidence Access
```

Do not collapse these into generic `ingest(JSON)` / `search(string)`.

## 11. Cognitive Query

`CognitiveQuery` is a typed intent AST, not an engine query.

It may express:

- text/free-form cues;
- exact refs;
- entities;
- Tags/Anchors;
- temporal constraints;
- source/authority constraints;
- modality;
- topology exploration;
- resource preference;
- evidence requirements;
- result projection;
- explicit semantic effort;
- required/preferred/optional capabilities.

Physical planner details remain internal.

## 12. Effort

Semantic effort:

```text
light
normal
deep
maximum
```

This expresses willingness to spend retrieval/cognitive work.

It must affect planning. It must not be a decorative enum or a fixed engine preset exposed as public architecture.

## 13. Learning and use

Retrieved candidates are not reinforced.

Meaningful stages must remain distinguishable:

```text
candidate
surfaced
inspected
selected/exposed
referenced/followed
useful downstream effect
explicit reinforcement
```

Repeated projection alone must not renew/strengthen cognition.

## 14. Multimodal cognition

Raw media remains addressable even with zero model providers.

When supported providers exist, useful textual/semantic surrogates may be persisted with exact source/producer provenance:

```text
image -> OCR / descriptions / region descriptions
audio -> transcript / segment/event descriptions
video -> transcript / scene/keyframe/temporal descriptions
```

Later runtimes with weaker capabilities can still retrieve these persisted derived representations.

## 15. Authority / Runtime / Projection

```text
Cognitive Authority
    durable semantics/provenance/revisions

Semantic Runtime
    current continuity/residency/use state

Serving Projection
    rebuildable lexical/dense/exact/topology artifacts

Model Cache
    disposable model-specific acceleration
```

Deleting a serving projection must not delete cognition.

Provider replacement must invalidate only affected derived/projection state.

## 16. No autonomous scheduler

Nous Wave exposes operations such as consolidation/backfill.

Invocation timing belongs to the Host/user/external scheduler/automation.

No nightly/cron/self-wakeup policy belongs in core.
