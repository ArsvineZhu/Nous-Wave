## 4. Decisions & Rationale

### 4.1 Nous Wave / Heptalogos 边界

- **Decision:** Nous Wave 正式承担 **Subject Cognition**；Heptalogos 正式承担 **Subject Agency / Product Runtime / Behavior Authority**。
  - **Why:** 两个项目过去都表述“主体认知”导致领域重叠。Nous Wave 已实际拥有 Memory、Cognitive Runtime、Session、ResidentSet、Query、Projection 基础，Heptalogos 已拥有 Reaction / BehaviorIntent / Review / DecisionCommit / CommunicationCommit / EffectOperation 等行为 Authority spine。按 cognition state/continuity 与 agency/action 拆分能降低长期重复实现与语义漂移。
  - **Alternatives rejected:** 两边各自保留一半 Memory/Persona/Context；Heptalogos 继续直接实现高级 cognition。
  - **Status:** confirmed
  - **Source:** joint conclusion / evidence-driven

### 4.2 Nous Wave 产品形态

- **Decision:** 正式采用 **Core + Client**。
  - `Nous Core = TypeScript Cognitive Host + Rust Cognitive Kernel`
  - `@nous-wave/client = 唯一正式程序化入口`
  - GUI、Heptalogos、CLI 都是 Client 消费者。
  - **Why:** GUI 管理、跨产品集成、协议稳定面都需要明确 headless product contract；不能让 GUI 或 Heptalogos 直接依赖 Rust 内部或数据库结构。
  - **Alternatives rejected:** GUI 直接访问 Kernel；GUI 单独 REST API；Heptalogos 专用接口。
  - **Status:** confirmed
  - **Source:** user + joint conclusion

### 4.3 Rust / TypeScript ownership

- **Decision:** Rust Kernel 保留：
  - Cognitive Authority
  - Memory / provenance / immutable revisions
  - transactions
  - Material / Artifact persistence
  - retrieval / ranking / serving/index
  - subject-scoped validation
  - Session/ResidentSet reliable runtime mechanics
  - runtime checkpoint persistence mechanics
- TypeScript Host 拥有：
  - Focus semantics
  - Projection policy
  - Managed Cognition / Context Epoch
  - Steward
  - model/provider runtime
  - NousQL parsing
  - public API
  - Client-facing configuration resolution
  - **Why:** 按可信度、事务性、性能和变化率划分，而不是按旧 crate 或语言历史划分。
  - **Alternatives rejected:** 全 Rust；全 TS；整个 Rust Kernel 变 Node native addon。
  - **Status:** confirmed
  - **Source:** joint conclusion

### 4.4 进程边界，不采用 N-API 承载 Kernel

- **Decision:** Kernel 作为独立 native sidecar/process；Host 可嵌入 Heptalogos 的 Node/TS 进程或独立运行。
  - **Why:** 保留故障隔离、Kernel standalone recovery/degradation、数据库与 Tokio 生命周期独立。
  - **Alternatives rejected:** napi-rs / Node-API 直接把整个 Kernel 编译为 Node addon。
  - **Status:** confirmed
  - **Source:** assistant recommendation accepted by direction

### 4.5 Protocol

- **Decision:** Public contract 使用 **Protobuf + Connect**；Host→Kernel private contract 使用 **standard gRPC + Tonic 0.14.x**。
  - TS Host 使用 `@connectrpc/connect-node` gRPC transport 调 Kernel；向 GUI/Heptalogos 暴露 Connect。
  - Buf 负责 schema lint / generation；Protobuf-ES 生成 TS 类型；Rust 由 tonic/prost 处理。
  - public namespace 与 private kernel namespace 分离，建议 alpha 命名如：
    - `nous.wave.v1alpha1`
    - `nous.wave.kernel.v1alpha1`
  - **Why:** Rust 侧无需为了 public browser contract 押注较新的 Connect Rust server；Tonic 0.14.x 是当前稳定成熟线。新的官方 Rust `grpc` crate 截至 2026-09 仍为 preview。
  - **Alternatives rejected:** `connect-rust 0.9` 作为关键 Rust server；自研 IPC；N-API；双套 public REST + Connect 长期并存。
  - **Status:** confirmed
  - **Source:** evidence-driven

### 4.6 Generated transport type containment

- **Decision:** protobuf / tonic / Connect generated types 仅存在于 transport adapter；不能进入 Rust domain model。
  - **Why:** 允许未来替换 Tonic/Connect 或协议代码生成而不污染 cognitive semantics。
  - **Alternatives rejected:** 把 generated message 当领域模型。
  - **Status:** confirmed
  - **Source:** joint conclusion

### 4.7 GUI Management Contract

- **Decision:** Nous Wave 必须具备完整 headless Management Contract + Client SDK，至少支持 Memory：
  - list/search
  - get/detail
  - revisions/history
  - evidence/source inspection
  - revise
  - suppress
  - restore
  - purge
  - artifact access
  - projection/readiness/status
- **Why:** Core + Client 是正式产品形态，不是未来 GUI 临时补丁。
- **Alternatives rejected:** GUI 专用 SQL/REST DTO；管理 API 只做 CRUD。
- **Status:** confirmed
- **Source:** user + joint conclusion

### 4.8 API 设计采用成熟标准语义

- **Decision:** 使用成熟 API pattern：
  - pagination: `page_size + page_token`
  - mutation concurrency: revision/ETag/CAS
  - generic partial update：FieldMask（仅适合普通字段）
  - domain operations 保持 custom methods
  - structured error：gRPC/Connect canonical status + richer error details
  - request idempotency：标准 `request_id` pattern
- **Why:** GUI 与 Heptalogos 都需要可靠并发、重试和分页；不应自研 protocol mechanics。
- **Alternatives rejected:** offset-only pagination、last-write-wins、字符串错误、盲重试、万能 PATCH。
- **Status:** confirmed
- **Source:** evidence-driven

### 4.9 Memory mutation semantics

- **Decision:** `Suppress / Restore / Purge / Consolidate` 是显式领域操作，不映射成通用 CRUD。
  - ordinary mutable fields 才可能使用 Update + FieldMask。
  - mutation 必须绑定 expected revision。
  - **Why:** 这些操作影响 Authority、provenance、serving projections、topology 与 purge lifecycle。
  - **Alternatives rejected:** `PATCH /memory/{id}`、`DELETE row`。
  - **Status:** confirmed
  - **Source:** joint conclusion

### 4.10 Observation idempotency

- **Decision:** Public Observation API 必须支持 `request_id` 幂等语义。
  - **Why:** Heptalogos durable WorkItem 重试可能再次调用 Nous；当前 `record_observation()` 每次创建新 `OccurrenceId`，`external_object_ref` 不是唯一键。
  - **Alternatives rejected:** 把 `external_object_ref` 强行当全局唯一键；盲目允许重复 Observation。
  - **Status:** confirmed
  - **Source:** evidence-driven, current code inspection

### 4.11 Artifact 与 Observation 分离

- **Decision:** 新 Public API 必须把：
  - persist/upload Artifact bytes
  - RecordObservation(artifact_ref)
  分成两个正式操作。
  - Client 可以提供 `observeFile()` 便利组合。
  - **Why:** 当前 `POST /artifacts` / `ingest_stream()` 实际会创建 ObservationOccurrence，弱化了项目核心 invariant `Artifact != ObservationOccurrence`。
  - **Alternatives rejected:** 上传文件即自动等同观察。
  - **Status:** confirmed
  - **Source:** evidence-driven

### 4.12 Blob data plane

- **Decision:** 大型 Artifact bytes 不塞进普通 unary protobuf。Control plane 用 Connect/Protobuf；blob data plane 用成熟 HTTP streaming / multipart / range，内部必要时可 gRPC streaming。
  - **Why:** 多媒体/大文件可能达到高体积；避免自造 chunk/resume protocol。
  - **Alternatives rejected:** giant protobuf `bytes`；自定义 chunk protocol。
  - **Status:** confirmed
  - **Source:** assistant recommendation / architecture conclusion

### 4.13 Session / Focus

- **Decision:** 现有 Rust `cognitive_sessions + resident_refs + cognitive_use_events` 保留为 reliable runtime mechanics；TS Host 拥有 Focus policy。
- 第一版 Focus：
  - `0..1 foreground`
  - `0..N suspended`
  - 真正并行任务使用多个 Session
  - **Why:** 不需要现在设计复杂 attention arbitration。
  - **Alternatives rejected:** 全 Session 迁 TS；一开始支持多个 foreground Focus。
  - **Status:** confirmed
  - **Source:** joint conclusion

### 4.14 RuntimeCheckpointStore

- **Decision:** Kernel 增加窄的 versioned RuntimeCheckpointStore，用于持久化：
  - FocusCheckpoint
  - Context Epoch metadata
  - Steward continuation/generation
- TS 拥有 payload 语义；Rust 只保证 durable/CAS persistence。
  - **Why:** 避免高变化 TS 认知 runtime 每次演化都触发 Rust domain schema 重构；又能恢复 Host restart。
  - **Alternatives rejected:** 把这些状态当 Memory；全部只放 Node heap；设计通用 object ontology。
  - **Status:** confirmed
  - **Source:** joint conclusion

### 4.15 Active Cognition

- **Decision:** Active Cognition 不建立第二套 Memory。
  - 应主要保存 Authority refs + runtime-derived state + minimal annotations。
  - Reaction ephemeral execution scratch 属于 Heptalogos ReactionWorkspace，不属于 Nous。
  - **Why:** 避免多套事实和 stale copies。
  - **Alternatives rejected:** Memory → Active Cognition DB → Session 三重复制。
  - **Status:** confirmed
  - **Source:** joint conclusion

### 4.16 Projection Runtime

- **Decision:** Projection 采用 contributor → typed contribution → planner → optional synthesis → renderer。
  - Memory/Persona/Relationship/Goal/Epistemic 等未来 cognition 都通过统一 Projection Runtime。
  - Heptalogos 不直接分别调用 `giveMeMemories()/giveMePersona()` 自己拼。
  - **Why:** 保持 consumer-specific cognition、budget、dedup、authority/provenance 一致。
  - **Alternatives rejected:** 各 cognition subsystem 直接生成最终 prompt string。
  - **Status:** confirmed
  - **Source:** joint conclusion

### 4.17 Managed Cognition

- **Decision:** Nous 只拥有 **managed cognitive context lane**；最终 `InvocationSpec/PromptProgram` 仍归消费者（例如 Heptalogos）。
- Context management protocol 收敛为：
  - `RESET(epoch snapshot)`
  - `APPEND(delta)`
- **Why:** 避免 Nous 与 Heptalogos 争夺最终 Prompt Authority；避免设计通用 JSON Patch/CRDT/OT。
- **Alternatives rejected:** Nous 拥有最终 system prompt；通用 diff language。
- **Status:** confirmed
- **Source:** joint conclusion

### 4.18 Model Runtime

- **Decision:** 长期只保留 TS Host 一套外部 ModelRuntime provider substrate；使用成熟 Vercel AI SDK Core。
  - Rust 保留 producer/derivation/Authority semantics，不长期维护第二套 provider HTTP SDK。
  - embedding、formation、Steward、Projection synthesis 等模型工作由 Host 调 AI SDK 后把 proposal/derived output 提交 Kernel。
- **Why:** 避免重复 provider SDK、streaming、structured output、middleware 实现。
- **Alternatives rejected:** Rust + TS 各自维护完整模型 Provider 层；通用 autonomous Agent framework。
- **Status:** confirmed
- **Source:** evidence-driven / joint conclusion

### 4.19 AI SDK usage boundary

- **Decision:** 采用 AI SDK 提供：
  - provider registry
  - `generateText/streamText`
  - structured `Output.object`
  - middleware
  - provider options
- 不让通用 Agent framework 接管 Nous cognition architecture。
  - **Why:** Nous 自己研究 Session/Focus/Projection/Steward/Context；双重 orchestration 会污染语义。
  - **Alternatives rejected:** LangGraph/general autonomous agent runtime 作为核心；ToolLoopAgent 作为 Nous 大脑。
  - **Status:** confirmed
  - **Source:** joint conclusion

### 4.20 Steward

- **Decision:** 实现为 `StewardEngine` / replaceable cognitive worker，而不是 autonomous agent authority。
  - 事件触发：turn boundary、focus switch、context pressure、explicit maintenance/checkpoint 等。
  - 输出 proposal，不直接写 Authority。
  - 无模型时 deterministic Projection 路径必须继续工作。
- **Why:** `LLM-enhanced != LLM-dependent`。
- **Alternatives rejected:** Steward 直接 mutation；独立自主 agent loop。
- **Status:** confirmed
- **Source:** joint conclusion

### 4.21 ResourceResolver 跨进程修正

- **Decision:** 当前 Rust 进程内 `ResourceResolver` trait registry 不能原样跨新 Host/Kernel process boundary。
  - 第一波保留 Resource Awareness、coverage/query dimensions、readiness 与 `ResourceActionSuggestion`。
  - 真正 current-authority external resolver 等出现具体 consumer 时，再由 Host-side provider 负责。
  - **Why:** 不应为了保存现有 trait 形态创建 Kernel→Host callback RPC。
  - **Alternatives rejected:** 直接把 Rust trait 抽象“网络化”；增加 callback protocol。
  - **Status:** confirmed
  - **Source:** evidence-driven

### 4.22 Config

- **Decision:** 第一波配置不采用重量级 config framework。
  - 使用显式 TOML + env override + typed validation；
  - `smol-toml` 被认为比 `c12` 更适合当前需要；
  - 不做 hot reload/watch/extends/remote layers。
- **Why:** `c12` 很成熟，但当前包含大量无需求 machinery；v4 仍 beta。
- **Alternatives rejected:** 自研配置解析；为了成熟度引入完整 c12 config discovery/watch framework。
- **Status:** confirmed
- **Source:** evidence-driven

### 4.23 Repository migration

- **Decision:** 目标形态：
  - `apps/nous-kernel/` — Rust
  - `apps/nous-core/` — TypeScript
  - `packages/client/`
  - `packages/protocol-ts/`
  - `proto/nous/wave/v1alpha1/`
  - `proto/nous/wave/kernel/v1alpha1/`
  - 现有 Rust crates 保留并按 owner 调整
- 不要一开始拆出 `session/focus/context/steward/projection/...` package forest。
- **Why:** 语言拆分不等于 package 拆分；按真实复用/独立 reason-to-change 再拆。
- **Alternatives rejected:** 大量细粒度 TS workspace packages；Nx/Turborepo 作为必需架构。
- **Status:** confirmed
- **Source:** joint conclusion

### 4.24 Old public Axum API

- **Decision:** 新 Public Client/Connect contract parity 后，旧 hand-written Axum public routes 应删除。
  - 迁移期间可短暂共存；
  - closure 时不得留下兼容双轨。
- **Why:** PRE_PRODUCTION 无兼容义务。
- **Alternatives rejected:** 长期 REST + Connect 双 public API。
- **Status:** confirmed
- **Source:** joint conclusion

### 4.25 Heptalogos integration

- **Decision:** Heptalogos 通过非常薄的 Nous adapter / capability provider 调 `@nous-wave/client`。
  - MessageFact 必须先成为 Heptalogos canonical truth；
  - 然后 durable obligation 送 Observation 给 Nous；
  - Nous BuildProjection 只提供 cognition；
  - Heptalogos 最终 PromptProgram、AIRuntime、BehaviorIntent、Review、DecisionCommit、CommunicationCommit、EffectOperation 仍留在 Heptalogos；
  - Use Feedback 再回 Nous。
- **Why:** 保持两个 Authority 系统清晰、可降级、可独立恢复。
- **Alternatives rejected:** Nous 直接控制行为；Heptalogos 直接访问 Kernel。
- **Status:** confirmed
- **Source:** joint conclusion / code-doc evidence

### 4.26 Basic Subject degradation

- **Decision:** Nous unavailable 时，Heptalogos Basic Subject path 必须仍能工作。
  - advanced cognition capability = DEGRADED/UNAVAILABLE；
  - basic Reaction/behavior path 继续。
- **Why:** Heptalogos current Subject Base 明确 advanced cognition 非硬 readiness dependency。
- **Alternatives rejected:** Nous down => Heptalogos Subject blocked globally。
- **Status:** confirmed
- **Source:** evidence-driven

### Failed / superseded direction

- **Tried:** 把 `connect-rust 0.9` 作为 Rust Kernel 的主要 server implementation。
  - **Result:** 被后续成熟依赖要求与 GUI topology 研究修正。

  - **Result:** rejected。
  - **Why it failed / what it established:** 破坏 process fault isolation、Kernel standalone recovery/degradation 与 native runtime lifecycle boundary。

  - **Result:** superseded。

  - **Retry?** avoid

  - **Result:** rejected for cross-process future.
  - **Why it failed / what it established:** 它是 process-local trait registry；网络化会诱发 Kernel→Host callback RPC。
  - **Retry?** only if a concrete current resolver consumer proves a cross-process provider contract is required
